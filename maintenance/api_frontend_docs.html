Documentación para Frontend - Endpoints creados

Esta página documenta los endpoints implementados para HU-PM-005 y el CRUD de repuestos. Incluye método, ruta, request, respuestas, validaciones y efectos secundarios.

1) Crear repuesto

Método: POST

Endpoint: /maintenance_spare_parts/create/

Request JSON

{
  "spare_part_brand": 6,
  "name": "Filtro de aceite",
  "spare_parts_cost": 120000
}

Respuesta 201 (éxito)

{
  "success": true,
  "message": "Repuesto de mantenimiento creado exitosamente",
  "data": {
    "id_maintenance_spare_parts": 2,
    "name": "Filtro de aceite",
    "spare_parts_cost": 120000.0
  }
}

Respuestas de error

  • 400 ValidationError (campos inválidos) 
    {
  "success": false,
  "message": "Error de validación",
  "details": {
    "spare_parts_cost": ["El precio por parte debe ser mayor a 0."]
  }
}
  • 401 No autenticado 
    {"message": "Usuario no autenticado"}

Validaciones y restricciones

  • El campo spare_part_brand debe referenciar una marca cuya categoría sea 4.
  • spare_parts_cost > 0.
  • Autenticación requerida. Chequeo de permisos comentado temporalmente.

Efectos secundarios

  • Ninguno adicional (solo creación del registro).

3) Crear reporte desde mantenimiento programado

Método: POST

Endpoint: /maintenance_scheduling/{id}/create-report/

Request JSON

{
  "title": "Reporte mantenimiento - Cambio de filtros",
  "description": "Se cambiaron filtros y se verificó el sistema hidráulico",
  "time_invested_hours": 2,
  "time_invested_minutes": 30,
  "recommendations": "Revisar correas en 500 horas",
  "maintenance_items": [1, 3],
  "spare_parts": [
    { "id_maintenance_spare_part": 2, "quantity_used": 2, "cost_at_time": 120000 },
    { "id_maintenance_spare_part": 3, "quantity_used": 1, "cost_at_time": 85000 }
  ],
  "responsible_user": 34
}

Respuesta 201 (éxito)

{
  "success": true,
  "message": "Reporte de mantenimiento creado exitosamente",
  "data": {
    "id_maintenance_report": 10,
    "title": "Reporte mantenimiento - Cambio de filtros",
    "total_cost": 325000,
    "machinery_serial": "S-0001",
    "machinery_name": "Tractor 1",
    "assigned_technician_id": 34
  }
}

Respuestas de error

  • 400 Programación en estado inválido (debe ser 13) 
    {
  "success": false,
  "message": "Solo se pueden crear reportes para mantenimientos en estado 13 (pendiente de reporte)",
  "details": "Estado actual: 12"
}
  • 400 Maquinaria en estado inválido (debe ser 6 antes de generar el reporte) 
    {
  "success": false,
  "message": "La maquinaria debe estar en estado 6 para poder generar el reporte.",
  "details": "Estado actual de la maquinaria: 4"
}
  • 400 Reporte duplicado para la misma programación 
    {
  "success": false,
  "message": "Ya existe un reporte para este mantenimiento programado",
  "details": "Reporte ID: 10"
}
  • 400 Validación de payload (ejemplos) 
    {
  "success": false,
  "message": "Error de validación",
  "details": {
    "spare_parts": ["Cada repuesto debe tener 'id_maintenance_spare_part'"]
  }
}
  • 401 No autenticado: {"message": "Usuario no autenticado"}

Validaciones y restricciones

  • El id en la URL es el id_maintenance_scheduling.
  • La programación debe estar en estado 13 para poder crear el reporte.
  • La maquinaria asociada a la programación debe estar en estado 6 al momento de crear el reporte.
  • Se requieren campos: title, description (≤ 600), time_invested_hours, time_invested_minutes, maintenance_items (IDs de maintenance), spare_parts (con id_maintenance_spare_part, quantity_used, cost_at_time), responsible_user.
  • Los repuestos deben existir y quantity_used > 0, cost_at_time > 0.

Efectos secundarios

  • La programación pasa a estado 15 (ejecutado).
  • La maquinaria pasa a estado 4 (activo).
  • Se crean relaciones:
    • maintenance_maintenance_reports entre el reporte y cada maintenance de maintenance_items.
    • maintenance_spare_parts_maintenance entre el reporte y cada repuesto aportado.
